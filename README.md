# 拾帧 Frame 0.3.0（公网候选版）

新增访客隔离、公开服务限额、Linux 媒体校验和中文 OCR，以及 Render Free 的 Docker 部署配置。公网版使用独立临时空间，不读取个人版登录文件；语音识别暂未配置。免费部署条件和限制见 `DEPLOY.md`。

2026-09-10：本地运行通过 78 项后端和 8 项前端状态测试；浏览器上传真实 MP4、播放、下载、文字保存及 390px 手机布局通过。三条历史抖音短链实际重试仍未返回可下载视频。因此本项目仍是候选版，不能宣称任意抖音链接可下载或已达到完整交付条件。

以下保留个人版使用说明与先前修复记录，旧版测试数量及环境障碍属于历史记录；最新验收结果以 `ACCEPTANCE.md` 为准。

在本机运行的视频与文字工作台。双击 `Start-Frame.cmd` 打开；从旧版更新后双击 `Restart-Frame.cmd`。启动器会确认服务属于本项目、保留现有数据，并拒绝在任务处理中重启。默认地址为 http://127.0.0.1:4175/ 。

## 这次改动

- 统一粘贴与按钮重试的排队流程：清除旧下载进度、文件信息和校验状态，保留三类文字；正在下载、识别或已有文件的任务不会重复下载。排队失败会释放任务，允许后续重试。
- 修复后台旧轮询覆盖重试结果的时序问题；重复粘贴和重试均会遵循自动提取选项，等待正在执行的识别结束，并跳过人工修改过或尚未保存的文字，包括人工清空的结果。
- 重启恢复被中断的识别任务时，保留已有文字、编辑标记和画面时间点。
- 启动器在停止旧服务前检查 Python、数据目录写入、数据库完整性、本机监听与平台连接。候选进程本地检查失败，或替换旧服务时无法联网，会保留旧服务；此检查不等于已验证完整重启或平台下载。
- 已定位抖音视频 ID 后，第一个页面返回 404、403 或超时仍会尝试对应的公开分享页，失败不会丢失视频 ID 或已读到的文案。
- 下载按清晰度尝试最多四个不同媒体地址，遇到 HTTP 错误、伪装成视频的 HTML 或截断文件时自动换地址；系统拒绝联网时立即停止。
- 重复粘贴失败或过期的链接会重试已有任务，保留人工编辑的文案；已经就绪或正在处理的任务直接复用。
- 重下文件从本次保存起保留 24 小时；不再因旧任务创建时间过早而立即清理刚下载的文件。
- 防止目标页面跳到另一条视频后，错误下载该视频的通用页面媒体。
- Windows 上对下载的 MP4/MOV/M4V 尝试读取首尾两帧画面，损坏或本机无法解码的文件会尝试备用地址。读取到的分辨率和时长优先使用实际文件数据。
- 解码组件缺失或超时会明确标注“播放校验未完成”，保留已下载的源文件；WEBM 仍只校验文件签名与传输完整性。首尾抽检不等于逐帧完整播放验收。
- 下载使用素材的中文标题和正确的扩展名，兼容浏览器的 UTF-8 文件名。

## 已有功能

- 抖音短链逐跳读取重定向，在加载目标网页前保留具体视频 ID；页面失败时继续用已定位的规范链接调用下载器。
- 短链展开超时仍尝试公开分享页。下载器的真实网络错误或平台错误不再被“通用首页”覆盖。
- 黑白、银灰与蓝色的紧凑界面，顶部导航、素材库筛选、并排预览和文字编辑。
- 接收整段分享内容、平台页面、MP4/MOV/WEBM 直链，以及公开网页中的 video/source、Open Graph 和 JSON-LD 视频地址。
- 抖音优先读取公开分享页的目标视频数据；未获取到时尝试本机 yt-dlp，并复用公开页面返回的匿名 Cookie。
- 小红书短链接会保留重定向后的签名参数，接入已有 yt-dlp XiaoHongShu 提取器。TikTok、B站继续使用对应提取器。
- 快手仅尝试公开网页媒体和页面中可读取的数据，不包含签名接口或登录浏览器自动化。
- 展示真实下载进度，校验文件格式与大小；中断下载不会变成可用视频，已取得的文案会保留。
- 重复提交相同且已下载或正在处理的链接时复用任务。
- 可勾选“同时提取口播与画面文字”，视频就绪后自动执行可用的本地识别。浏览器准备画面和音轨时需要保持页面打开。
- 平台连接中可导入或移除所选平台的 Netscape Cookie 文件；不再要求通过环境变量才能配置。

用户已选择先完成本地修复。本轮启动前检查测试中的外网请求均使用模拟结果，未替换现有后台，也未执行实际联网预检或浏览器验收。

## 平台登录文件

公开内容先直接获取。仅在需要时，在网站“平台连接”中选择对应平台，导入自行导出的 Netscape Cookie 文本文件。格式支持普通 Netscape 会话字段与常见导出器使用的 0 到期时间。

文件只存放在 `data/credentials`，仅保留所选平台的未过期条目，不向浏览器返回 Cookie 值，不会自动读取用户浏览器账户。导入立即生效，回到原任务点击重新获取即可。文件是登录凭据，不要上传到聊天、共享盘或公开仓库。可以在平台连接中随时移除。

兼容启动环境中的 `CLIP_COOKIES_FILE` 配置；自行使用该配置时，需要在启动环境移除变量才能完全停用。

## 运行和数据

需要 Windows、Python 3.10+。启动器复用本机现有 Python，无前端构建和独立数据库服务。平台回退解析需要可用的 yt-dlp，中文画面识别使用 Windows OCR。

```powershell
python server.py
```

直接运行默认端口为 4173；启动器使用 4175 到 4190 的可用端口。服务仅监听 127.0.0.1，不是公网托管网站。

- 媒体文件：`data/media`。上传最大 500MB。
- 文字与历史：`data/workbench.sqlite3`。
- 媒体保留 24 小时，运行期间定期清理；文字保留至手动删除。
- OCR 与语音最长 10 分钟；OCR 最多 150 帧，快速切换字幕可能遗漏。
- 语音优先使用 `CLIP_WHISPER_MODEL` 指定的本地 faster-whisper 模型，否则检测 Windows 系统识别器。服务可用性不等于转写准确率，结果应人工校对。
- 模型只从配置的本机目录读取，不在处理素材时自动下载。

本地 Whisper 的可选安装：

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install faster-whisper yt-dlp
$env:CLIP_WHISPER_MODEL = 'D:\models\faster-whisper-small'
.\.venv\Scripts\python.exe server.py
```

## 10013 联网错误

10013 表示系统拒绝了后台进程的连接。用户浏览器能联网，不代表受限环境启动的后台能联网。

请在 Windows 文件管理器中双击 `Restart-Frame.cmd`，从用户的正常启动环境重启。启动器不会修改防火墙，不需要管理员权限。若仍失败，应检查该进程的联网规则；重启不能保证消除系统策略或平台限制。
